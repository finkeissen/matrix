# 0.foundation

## Scope

This domain contains **descriptive, time-bound, and conflict-capable information
about the epistemic state of the Matrix**.

It is the place where **arguments about arguments**
are made explicit.

The focus is **not technical infrastructure**,
but the **assumptions, distinctions, and argumentative conditions**
under which the Matrix exists and changes.

This domain does **not** define rules.
It records and exposes **claims, interpretations, critiques, and revisions**
about how the Matrix is understood at different points in time.

---

## What this domain is

`0.foundation` is a **reflexive domain**.

It contains explicit statements about:
- how the Matrix is *conceptually understood*
- which distinctions are assumed or contested
- which argumentative moves are considered admissible
- how different system states are interpreted
- how responsibilities, scopes, and boundaries are argued about

This includes, but is not limited to:
- claims about the design and intent of:
  - the research-program
  - MMS
  - the Matrix
  - the matrix-gateway
- competing interpretations of system goals or limits
- disagreements about terminology and framing
- recorded shifts in how the system is understood over time
- unresolved tensions between alternative conceptualizations

All content in this domain is:
- explicitly formulated
- attributed
- temporally bound
- revisionable
- conflict-capable

No statement in this domain has privileged or binding status.

---

## Why this domain exists

Large Language Models make it possible to **separate argumentative substance
from technical implementation**.

This domain exists to take advantage of that separation.

Here, we do **not** discuss:
- hardware
- software architecture
- performance
- optimization
- implementation details

Instead, we focus on:
- arguments
- assumptions
- conceptual states
- transitions between ways of thinking

The technical system is treated only as a **carrier**.
The object of interest is the **argumentative configuration** it enables.

---

## Layer distinction (important)

This domain may refer to system components such as:
- `research-program`
- `mms`
- `matrix`
- `matrix-gateway`

However, these are treated as **objects of argument**,
not as sources of authority.

Distinctions between layers are expressed:
- **within claims**
- via explicit scope fields
- via argumentation and critique

They are **not enforced through directory structure**.

This ensures that:
- a single claim may concern multiple layers
- tensions between layers remain visible
- no component gains implicit authority by structural separation

---

## Information structure

All content in this domain is stored as **information**, not data.

The system does not operate on “data” as something given or objective.
It operates on **information**:
- formulated
- attributed
- contextual
- contingent

Typical contents include:
- `claims.jsonl`
- `relations.jsonl`
- `sources.jsonl`

These files contain **information artifacts**,
not facts and not rules.

---

## What this domain is not

`0.foundation` is **not**:
- a specification
- normative documentation
- a definition of correct usage
- a replacement for `/handbook`
- a replacement for `/system`
- a source of constraints for MMS execution

Normative rules and hard constraints remain exclusively in:
- `/handbook`
- `/system`

This domain describes **how the system is argued about**,
not how it must behave.

---

## Relationship to other layers

- `/handbook`  
  Defines **how the repository should be read**.

- `/system`  
  Defines **formal structures and constraints**.

- `domains/0.foundation`  
  Describes **what is said, assumed, or disputed about the Matrix
  as an argumentative system** at different points in time.

This separation is intentional.

---

## Equality with other domains

This domain is treated **exactly like any other domain**.

- Its claims may be contradicted.
- Its interpretations may change.
- Its internal disagreements are preserved.
- Its statements may become obsolete.

The Matrix has **no immunity** from being represented,
questioned, or criticized within itself.

---

## Design Principle

> The Matrix does not claim authority over arguments.  
> It only makes their structure explicit.

---

## Status

This domain is expected to evolve continuously.

Its purpose is not stability,
but **traceability of argumentative states**.
